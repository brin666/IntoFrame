# IntoFrame architecture and implementation plan

## Stage 0: checked environment and choices

The workspace was empty at project start. The development PC has Node 24, Python 3.14 and 3.11, an RTX 4060 Laptop GPU with 8188 MiB VRAM, and FFmpeg. Python 3.11 is used for the image-service virtual environment. BiRefNet and Depth Anything V2 Small have both passed real local inference on this GPU.

| Concern | Choice | Reason |
| --- | --- | --- |
| Web app | Vite, React, TypeScript | Small client bundle and immediate local reload; no server rendering needed. |
| API | FastAPI | Validated upload, explicit processing states, separate model adapter. |
| Segmentation | Official BiRefNet via PyTorch, FP16, 1024-square input | Detail-friendly salient-object mask; the official repo describes roughly 3.45 GB GPU memory on RTX 4090 at this size, which is an estimate, not a measurement on this PC. |
| Image geometry | One canonical EXIF-corrected RGB image, longest edge ≤1600 px; mask resized to its exact width/height | All pixels stay in one coordinate system. No web-layer guessing about EXIF or image fit. |
| Static renderer | Two aligned image layers and stationary letterbox bars | The background cannot paint over the bars; the transparent foreground can. The same transform is applied to both layers, preventing duplicate silhouettes while stationary. |
| Stage 2 renderer | Three.js full indexed alpha mesh with native float32 relief above stationary bars; shared surface for retained scene | Perspective camera motion produces local relief while source-center projection and subject/support contacts stay aligned. |
| AI style MVP | Local SD1.5 Inpainting sky generation, original subject mask composite | Serialized, no paid API calls, preserves subject detail/alpha and keeps the existing pop-out and depth renderer. Pink/Night apply a mild shared scene RGB curve. |

## Data contract

`POST /api/jobs` accepts multipart `file` and returns a job ID. `GET /api/jobs/{id}` returns `processing`, `complete`, or `failed` and the current stage. A completed result gives `sourceUrl`, `maskUrl`, `subjectUrl`, `width`, `height`, `subjectBounds`, and `composition` (`scale`, `focusX`, `focusY`). The image and mask are at the same resolution; bounds are source pixel coordinates. Files are under `backend/data/<job-id>/`.

`POST /api/depth` accepts `{"jobId":"..."}` only after segmentation completes. `GET /api/depth/{id}` reports processing status and returns the result. A single Depth Anything inference supplies the compatibility native `depth.png`, padded `render-depth.png` and padded `background.webp`, plus native `subject-depth-f32.bin` in little-endian row-major float32. The result keeps source/render dimensions, padding and representative `foregroundDepth`; PNG grayscale 0 means farther, 255 means nearer. PNG percentile normalization and Gaussian smoothing remain compatible; the float32 asset preserves unclipped local relief. `meshDepthMetadata` records native dimensions, subject P05/P95/median, global range statistics and the model pin; `meshDepthDiagnostics` reports eligibility and reasons for empty/flat/weak subject ranges. No-opaque-subject results omit the raw asset. Native source, alpha and float32 depth share exact EXIF-corrected coordinates; padded RGB/PNG assets share a second coordinate system. Neither signal is metric distance.

`POST /api/restyle` accepts `{"jobId":"...","style":"dreamy-pink"}` after segmentation. Styles are `dreamy-pink`, `golden-hour`, and `cinematic-night`. `GET /api/restyle/{id}/{style}` reports queued/loading/generating/compositing status, then URLs for lossless native generated `background.webp`, source-resolution `composite.png`, recovered-edge `subject.png`, and lossless padded `render-background.webp`. Styled subject stays above the bars; original view and experiment keep the original foreground. Source RGB is lossless, so all layers use one canonical set of pixels. Failed jobs can retry without duplicate active tasks.

## AI style pipeline

During upload, BiRefNet supplies subject alpha and a pinned CPU SegFormer B0 supplies independent sky probabilities/class labels. The result includes `subjectStats` (actual occupancy and side-contact row fractions) and `sky` (eligibility, reason, status, bounds, mask URL, confidence coverage and model pin). Sky requires >=1% area and >=90% high-confidence coverage of candidate sky. Reliable boundaries grow at most 12 native pixels inside semantic sky; the final feather is 2px inward. Alpha>=2 is excluded. No-sky, broad ambiguity and unavailable inference return still preview with Generate disabled; POST independently rejects422 before scheduling. The detector is licensed for noncommercial research/evaluation.

SD1.5 synthesizes an independent sky field on neutral RGB, with existing640px/22step/crop settings. `sky_compositing.py` replaces only confirmed editable sky. `atmosphere.py` grades synthetic sky at crop resolution before enlargement: continuous pastel pink clouds, or blue-hour clouds without star extraction. The subject and retained non-sky scene then share one pointwise RGB curve, preserving their geometry/alpha and support-contact color consistency; Golden Hour stays byte-identical to its previous color path. Telea approximates occluded subject pixels, and nearest nearby sky coverage is extended only underneath the subject. Edge recovery precedes scene color treatment and is limited to subject boundaries adjoining changing sky; alpha remains identical.

After the unchanged suitability gate, `sky_refinement.py` resolves local coarse-label sky omissions using native RGB, fine subject alpha, semantic class constraints and four-neighbor connectivity to existing sky. Reach is four model cells capped at64px; high-confidence other classes and disconnected holes remain protected. It does not use inverse alpha as the scene's editable mask. Actual logits/coarse masks are retained for diagnosis. The captured Big Ben false-negative sky patch had alpha0, editable0 and preserved-scene alpha255; refinement changes sky weight, not subject alpha or camera. Large Eiffel interior openings remain a documented visual failure. See [repair evidence](docs/SKY_EDGE_REPAIR.md).

Each style saves lossless native `background.webp`, `subject.png`, `composite.png`, padded `render-background.webp`, `render-sky.webp` and RGBA `render-scene.png`. The flattened native/padded backgrounds are composites of these same layer pixels; no separate dynamic color generation is used. `backgroundGeometry: "sky-layers"` and the two URLs are attached to the current visibleDepth identity. Native background is used by PNG; padded flattening is the still fallback. Three.js raster/linear blending may differ at a narrow antialiased boundary from browser/PIL sampling; screenshot pixel identity is not claimed.

Palette updates use `styles/<style>/<atmosphereVersion>/` URLs and version-aware frontend/backend cache reuse. Old generated assets remain intact; Generate/Update atmosphere schedules a fresh result. `model-sky-raw.png` records the actual ungraded diffusion output. PNG, Remotion transition and spatial preview all consume the same versioned subject/background pixels. Color balancing is not neural relighting; original shading and material detail remain.

Original uploads and After render a full indexed alpha mesh with bounded native depth relief. After keeps sky flat at virtual z=-0.8; subject and retained scene sample one shared native surface, preserving feet/support contacts. Subject P05/P95/median normalize local relief to at most +/-0.36 around representative subject z=.78-.98. Alpha-weighted samples avoid unrelated sky at silhouettes, geometry extends beneath transparent pixels, and bounded slopes soften depth steps without rejecting triangles or thin ornaments. `(C-z)/C` XY compensation and affine screen UV interpolation reproduce the centered input at vertices and triangle interiors. The subject mesh renders above stationary 13% bars. Before comparison stays still; old photo depth is never imposed on edited sky. This remains shallow 2.5D relief, not accurate perpendicular walls, backsides or per-object reconstruction.

`parallax.ts` derives maximum camera travel from a CSS-pixel separation target: `zoom*focalPixels*(1/(C-zSubject)-1/(C-zBackground))`. Desired separation stays 4-6px on desktop and 2.8-4px for touch before safety caps. Nearest actual mesh depth enters overscan and source-cut safety; actual camera Z stays fixed at C=3.5. A source cut can permit one-sided motion; no safe room produces a notice. Resize/crop recalculate caps, and every controller update clamps the final camera. Increased travel alone does not demonstrate local relief. PNG uses the shared center composition independently of camera state.

Original uploads and completed After scenes gently animate once readiness belongs to the current `DepthResult` identity. `sceneMotion.ts` uses 35% of safe travel on a 16-second cycle. A press freezes the current pose and phase; a ref stores normalized horizontal displacement without per-frame React updates. Drag takes over the bounded horizontal camera, and release blends back to the paused automatic phase with the same spring. Mouse captures immediately; touch waits for horizontal intent, while `touch-action: pan-y` preserves vertical scrolling. Captured horizontal movement can continue outside the stage within the same camera limits. Cancel/lost capture ends dragging; resource switches, Before/mask/generation/reduced motion and hidden/unfocused pages clear input and pause motion. A previous texture cannot enable a new scene. Missing/weak/invalid native depth or graphics loss leaves a static fallback. [Local interaction finish](docs/LOCAL_INTERACTION_FINISH.md) records this contract; [Depth motion repair](docs/DEPTH_MOTION_REPAIR.md) records the preceding native-mesh checkpoint.

## Stage 1 rendering geometry

The static composition renders the source into a full canvas clipped to the central 74% aperture. Opaque black bars cover the top and bottom 13%; a transparent PNG made with BiRefNet's alpha renders after the bars. Source and subject receive the same composition transform, preventing a duplicate silhouette inside the aperture. Head or feet outside the aperture remain visible over the bars. The bounded initial scale comes from mask bounds; the zoom slider corrects framing. This still view appears while depth loads and remains the fallback when motion is unavailable.

## Stage 2: implemented spatial motion

1. Depth Anything V2 Small runs once after segmentation. One native float32 prediction supplies both the existing percentile-normalized/smoothed 8-bit PNG and the raw native asset plus subject statistics/diagnostics. AI work remains serialized.
2. OpenCV Telea approximates pixels hidden by the subject; 6% reflected overscan supplies edge pixels. Short travel bounds limit exposure of this approximation.
3. `depthGeometry.ts` decodes and validates native dimensions, encoding, finite samples and subject range. It builds a complete indexed grid, samples bounded local relief around the representative depth, extends geometry beneath transparent pixels and limits depth slopes. Alpha remains the texture silhouette; triangles are not discarded.
4. `SpatialFrameScene.tsx` renders the subject on that surface above stationary bars. Generated After renders retained scene on the same surface and sky on a distant flat plane. Original uploads use their photo-depth background and native subject mesh. Perspective-compensated positions plus corrected screen UV interpolation recover the center-view photo; generated sky never receives old photo depth.
5. The horizontal camera uses the existing desktop/touch separation targets and spring, capped by overscan, nearest actual mesh depth and source cuts. Automatic motion uses 35% of the safe range; a live pointer ref takes over during drag, then blends back on release. Camera Z stays fixed. Readiness follows the current scene; Before/mask/generation/reduced motion and hidden/unfocused pages stay still. Unavailable native relief or a lost context restores static fallback. Centered still PNG export remains unchanged.
6. `scripts/test-depth-contract.py`, `scripts/test-depth-geometry.mjs` and `scripts/test-scene-motion.mjs` check the artifact/geometry/controller contracts without inference. `scripts/drag-motion-browser.mjs` uses frozen cached source/depth/sky assets for current browser evidence. See [Local interaction finish](docs/LOCAL_INTERACTION_FINISH.md). The previous hold harness and depth report remain checkpoint history. Phone emulation and callback timings do not establish physical phone/display performance.

## Main risks and gates

- **Actual BiRefNet runtime:** verified on this RTX 4060 with PyTorch 2.11 CUDA 12.8, including a fresh model download, cached model reload, and three image categories. Time and VRAM observations are recorded in README; test again on another PC.
- **Segmentation quality:** test a person with hair, a pet with fur, and an object or scene. Mask holes and ambiguous subjects require selection or brush edits; stage 1 does not yet provide those edits.
- **Disocclusion:** a depth mesh cannot invent surfaces hidden behind the subject. Inpainting or a tight camera bound is required before stage 2 motion ships.
- **Single-photo depth:** relative depth can be noisy around edges and reflective materials. Use smoothing and conservative camera travel, and compare result visually rather than claiming physical reconstruction.
- **Model weights and memory:** both models ran locally in the same process with serialized inference. A spot GPU reading after both loaded was 5044 MiB used, including other processes. Keep inference on uploads only; test again under competition-day GPU load.

## Delivery sequence

1. Stage 1: verify model on this PC, inspect masks on at least three categories, improve composition and mask correction, capture first screenshots.
2. Stage 2: depth artifact, perspective grid, hold interaction, occlusion and travel limit, browser FPS measurement. Free drag exploration remains future work.
3. Stage 3: licensed inpainting model, edge cleanup, dynamic bars, mobile layout and optional sensor motion.
4. Stage 4: three-category QA, README, screenshots, and an under-three-minute demo script/video.
